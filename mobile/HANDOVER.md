  日夜主题(外观按钮点一下切 跟随系统→浅色→深色);**蓝色只给「连接/重试」这一个实心按钮**。

### M2 主机密钥校验(第四次会话,真机验证)
- **核心** `xssh-core/src/ssh.rs`: `Target.known_key` + `verify_host_key()` → `HostKeyVerdict::{Trusted,Unknown,Changed}`;
  `check_server_key` 只对 `Trusted` 返回 `true`,其余拒绝握手;`connect()` 把 russh 的笼统错误换成
  `SshError::HostKeyUnknown{fingerprint}` / `HostKeyChanged{expected,actual}`。3 个单测(共 15 passed)。
  **指纹逐字节比对**:`SHA256:` 后面是 base64,大小写有意义,只 `trim()` 首尾空白。
- **FFI**: `HostConfig.known_key`;`FfiError::{HostKeyUnknown,HostKeyChanged}`,
  Display **就是指纹**(`flat_error` 只带文本过边界,见坑 18)。
- **Kotlin**: `Host.keyFingerprint` 落 SharedPreferences;`TerminalScreen` 出确认页/告警页;
  `App` 的 `onTrustKey` 写回主机并换新 `Host` 实例触发重连;
  `HostEditorScreen` 保存时**同端点保留、改了地址或端口则清空**指纹。
- **真机验证**(`adb reverse tcp:2222 tcp:22` → 本机 OpenSSH):
  ① 没信任过 → 弹「首次连接这台主机」+ 指纹,不连;② 点信任 → 连上,指纹落盘;
  ③ 存了错指纹 → 「主机密钥已改变」并列出两个指纹,不连;④ 点「仍然信任新密钥」→ 连上并覆盖;
  ⑤ 指纹正确 → 静默直连。另验证:改名保存后指纹还在;端口 2222→2223 保存后指纹清空。
- 桌面版 CLI `xssh-devssh --known-key <指纹>` 同样走这条路径(三种结果均已手验)。

### M2.8 二次复核(第五次会话收尾)
把这次会话改过的代码全过了一遍,查出并修掉:
- **[真 bug] 系统返回键不断开会话**。会话没有明确的归属人:只有「断开」按钮和 pump
  循环里 `!alive` 分支会关。按系统返回键回主机页后,远端 shell 一直挂着,直到进程被杀。
  A/B 实测(同一套脚本,只换 APK):改前回到主机页 15 秒后连接数仍是 1,改后是 0。
  现在会话由 `DisposableEffect(live)` 统一持有,离开这一屏的**任何**路径都断,
  并且用进程级的 `sessionCleanup` 作用域执行 —— `rememberCoroutineScope()` 会随界面
  一起被取消,关闭动作可能还没调度就没了。
- **[真 bug] 连接被取消时会话泄漏**。`connectHost` 是阻塞调用,用户在 15 秒超时内退出时
  协程被取消,`withContext` 直接抛 CancellationException,刚建好的会话没人拿得到也没人关。
  改成在 IO 块内检查 `isActive` 并就地关掉。
- **[性能] 空闲终端烧掉小半个核**。实测 46% CPU(主机页基线 3-4%)。每帧都把整屏文字
  跨 FFI 搬回来,60 次/秒。现在 `pump()` 报告屏幕有没有变,没变就不取;空闲半秒后降到
  96ms 一帧。**46% → 12-13%**。降频会让停顿后第一次按键的回显慢近 100ms(终端里最能
  感知的延迟),所以 `sendRaw` 会把轮询立刻拉回 16ms。
- 去掉三处 `!!`(`onTrust` 里的 `pendingKey!!` 是稍后才执行的,等于赌它那时还非空)、
  `KeyCap` 没人用的 `wide` 参数、4 个未使用 import;所有文件的 import 重新按字母排序;
  `SENTINELS` 那段被存成 \uXXXX 转义、源码里根本读不了的 KDoc 改回中文。
- Rust 侧:`cargo test` 15 通过、clippy 干净。`cargo fmt --check` 有 39 处差异,但分布在
  6 个文件(含本次没碰的 `terminal.rs` / `devpty`)—— 是项目从没跑过 rustfmt,
  不在这次改动范围内,建议单独做一次全量格式化。

**复核中我自己判断错了两次,都靠控制变量纠正**:一是怀疑「断开」按钮有协程竞态,实测
它一直是好的;二是第一次测返回键只按了一次 —— 那只收起了输入法,应用还在终端页,
于是先误判「泄漏」、又误判「修复无效」。**测之前先确认当前在哪个界面**。

### M3.1 会话存活(P0-1,已上机)
**产品定位已定:移动端做「运维遥控器」,不做缩小版桌面。** 不与桌面端功能对齐。
排期:会话存活 → 多会话/双终端 → 回滚缓冲 → 密钥库 → 外屏片段 → MIUI 引导(发布前收口)。

会话原来归界面所有,离开那一屏就断。现在:
- `Sessions.kt`:`SessionRegistry`(进程级单例)持有所有会话,`TerminalSession` 自带轮询
  循环。界面只是观众 —— 来了收 `frame: StateFlow`,走了会话照跑。
- `SessionService`:前台服务 + 常驻通知(带「全部断开」动作)。它不碰 SSH,唯一作用是
  让系统别冻结/回收进程。第一条会话开启时拉起,最后一条关闭时自己退场。
- 只有两处会真的关会话:终端页的「断开」、通知栏的「全部断开」(以及对端自己断)。
- 主机卡片上加「运行中」标签;再点进去是**接管**,不重连、也不再问一次主机密钥。

为什么非要前台服务:服务端数据是往 `mpsc::unbounded_channel` 里堆的,没人收就一直涨;
而进程一被冻结,连接直接断。

**真机验收(全部通过)**:
| 场景 | 结果 |
|---|---|
| 连上后退回主机页 | 连接仍在,卡片显示「运行中」 |
| 切到桌面 60 秒 | 连接仍在 |
| 回到应用再进终端 | 接管同一会话,`KEEP-ALIVE-MARK` 输出还在,连接数不变(没重连) |
| 点「断开」 | 连接归零,服务退出,通知消失 |
| 后台 CPU | 8% → **3%** |

后台降耗的关键:不能只看 `frame` 有没有收集者 —— Activity 只是 stopped 时组合没销毁,
`collectAsState` 还在收,判断永远为真。加了 `AppVisibility`(Activity 的 onStart/onStop),
真在前台才 16ms 取整屏文字,切走就退到 250ms 且只收数据不取画面。

**未完**:`POST_NOTIFICATIONS` 在 Android 13+ 要运行时授权,没给的话服务照跑但常驻通知
不显示(=后台挂着连接却没有可见提示)。连接前会弹一次请求;授权后的通知显示效果尚未验证。

### M3.2 行高(全应用)
用户发现终端头部「主机名 / 地址」之间的缝过大。量出来根因不在那一处:

### M3.4 回滚缓冲(P1,已上机)
定位是「运维遥控器」,主要动作就是看输出,而之前**一行都翻不回去** —— 输出滚过去只剩
最后一屏。所以把这一项提到了多会话前面。

- 核心 `terminal.rs`:`scroll(lines)` / `scroll_to_bottom()` / `scroll_offset()` /
  `history_len()`。`scrolling_history` 本来就配着(10000 行),`display_iter` 也本来就
  跟随显示偏移 —— 取行的逻辑一行没改。两个新单测(共 17 passed)。
- FFI + Kotlin:`TerminalFrame.scrollOffset`,界面据此显示「↓ 回到底部」。
- 手势在**画布**上(不在外层):单指拖动翻历史;**两根手指就 break**,把事件让给外层的
  捏合缩放;而且只在真的翻过一行时才 `consume`,轻点照样聚焦弹键盘。
- `sendRaw` 会先 `scrollToBottom()`:翻着历史时敲键盘却看不见自己的回显,是最让人困惑的状态。

**真机验收**:拖动能翻出更早内容;翻上去后跑 `ping` 持续输出 6 秒,**终端区域像素级无变化**
(视口锚住了);「回到底部」有效;打字自动回到底部;轻点不会被误判成滚动。

**测试脚本的坑(又踩一次)**:`tap_label` 原来只算一次坐标,键盘弹出导致布局移位后,
后面几次点击全打空,看起来像「按钮没反应」。已改成每次重新定位。

- 分栏判据从 `Configuration.screenWidthDp` 改成 **BoxWithConstraints 实测到的窗口宽度**。
  分屏时部分机型的 `screenWidthDp` 仍报整块屏幕的宽度,那样会在只有半屏宽的窗口里摆双栏:
  左栏按折痕位置占满整个窗口,右栏被挤出窗口 —— 表现就是"内容跑到右边"。
  另加一道兜底:左栏宽度 `coerceAtMost(窗口宽 - 280dp)`,无论如何吃不掉整个窗口。
  **注意:这条是按代码推断做的防御性修复,未能在真机上复现分屏场景**
  (MIUI 下 `--windowingMode 6` 只是把窗口标成 `mInSplitScreen=true`,bounds 仍是全屏;
  `--activity-launch-adjacent` 被系统拒绝)。需要人工进分屏验证。

### M3.10 冷启动闪跳(定位过程值得看)
现象:内屏展开、应用完全关闭时打开,右栏内容会闪跳一下才正常。

**两次错误假设,都被录屏否掉**:
1. 以为是 Android 分屏下 `screenWidthDp` 报整屏宽导致摆错双栏 —— 改成用实测窗口宽度
   (这个改动本身是对的,留着),但**不是本症的成因**。
2. 以为是 `WindowInfoTracker` 异步,第一帧 hinge 为 null 走了 38% 兜底宽 —— 录屏显示
   应用出现的第一帧右栏左缘就是 465dp,和稳定态一致,**没有这个跳变**。

**真正的成因**(靠逐帧录屏拍到):自动选中第一台写在 `LaunchedEffect` 里,而副作用要等
第一次组合**之后**才跑。于是冷启动时右栏先渲染一帧「选择左边的主机」的空状态,
下一帧才换成真内容 —— 录屏第 296 帧拍得清清楚楚。
改成在**组合期间**就算出要显示哪台:`hosts.firstOrNull { it.id == selectedId } ?: hosts.firstOrNull()`。
改后重录:右栏一出现就是主机详情,全程没有空状态。

**方法**:一帧的闪跳用 `uiautomator` 追不上(每次 ~1 秒)。用
`adb shell "nohup screenrecord --time-limit N ... &"` 在**设备侧脱离**启动
(放在后台任务里跑会随 shell 一起被杀,只录到 4 帧),再用 PyAV 逐帧解。

### M3.11 冷启动闪跳其实有两个成因(第二个)
第一个(空状态闪一帧)修掉后**还在闪**。继续逐帧量,拿到硬数据:

```
帧 56-57  左栏卡片右缘 311dp   ← 栏宽 327dp = 860 x 38% 的兜底值
帧 58 起  左栏卡片右缘 413dp   ← 栏宽 430dp = 真实折痕位置
```

左栏从 327 撑到 430,右栏内容整帧右移约 100dp —— 就是用户说的"跳到右边"。

也就是说**我最早那个"折痕异步到达"的假设是对的**,中间一度把它否掉是因为那次量错了
元素(把详情栏的按钮当成了左栏卡片)。教训:否定一个假设要和确认它一样严格。

修法:`UiPrefs` 缓存上次量到的竖直折痕位置(按窗口宽度存),`rememberAdaptive()` 在
`WindowInfoTracker` 回调到达之前先用缓存值。折痕位置在同一台设备上是固定的,所以第一帧
就是对的;首次安装后的第一次启动仍会跳一次,之后不会。半折(tabletop)是临时状态,不缓存。

验证:同一段分析脚本跑改前/改后两段录屏,"列表出现后左栏卡片右缘"的取值集合里
**311 消失了**。

### M3.12 新建/编辑主机改成移动端排法
原来是桌面表单:每个字段一个 Material 描边输入框,装在卡片里,顶栏放「返回/保存」。
在手机上这套既占地方,又把一行拆成"框 + 标签"两层。

新增 `Form.kt`,按分组行式列表重做:
- `FormGroup` 一组字段一块圆角面板,组标题在面板外、脚注在面板下;
- `FormField` 一行:左标签、右取值,值用 `BasicTextField` 自己画(不用描边框);
  长值(私钥路径)用 `stacked = true` 改成上下排 —— 右对齐单行放不下路径,只会从中间切掉;
- `FormDivider` 行间细线左侧内缩,读起来才是"同一组的下一行";
- `Segmented` 私钥/密码用分段选择,一眼看出是"几选一"而不是"两个都能按"。

页面本身:标题回归内容(28sp)、保存/返回进右边缘轨道、**展开的内屏按折痕分两栏**
(左「连到哪台」右「怎么登录」),窄屏单列且限宽 640dp 居中。

真机验收:内屏双栏与外屏单列均正常;私钥路径两行完整显示;所有文字左缘 32.0dp;
脚注止于 329.8dp(内容区上限 357dp,不越界);端到端点行输入 → 保存 → 列表出现。

### M3.13 登录方式默认密码 + 外屏兼容性复核(第六次会话)

**1. 默认密码。** `Host.auth` 的默认值改成 `PASSWORD`,分段选择里「密码」在前、
「私钥」在后,凭据字段跟着换序。手机上密码更常见,也不需要先把私钥弄进设备。
`HostStore.load()` 的反序列化默认值同步改掉 —— 它原来是"不等于 password 就算 KEY",
和数据类的新默认值相反。

**2. 折痕缓存被外屏顶掉(真 bug,复核时靠读设备 prefs 才发现)。**
M3.11 加的折痕缓存只有**一个槽**,键是窗口宽度。外屏跑一次就把内屏那条记录覆盖了:

```
foldWindowWidthDp = 623   foldStartDp = 192.7    ← 外屏写进去的
```

于是"折一下 → 在外屏开一次 app → 再展开冷启动",M3.11 修掉的闪跳原样回来。
改成**一个窗口形态一个槽**(`fold_<宽>x<高>`),并且只缓存**真能拿来分栏**的折痕
(判据与 `listPaneWidth` 同源:`200dp < start < 宽-200dp`)—— 折叠之后系统仍会报一条
折痕,位置却落在外屏窗口的 192dp 处,拿它分栏只会切出两条窄缝。

实测四条记录并存、互不覆盖:

```
fold_860x608 = 429.8   ← 内屏横屏,真折痕
fold_608x860 = -1      ← 内屏竖屏,折痕是水平的,不能分栏
fold_623x425 = -1      fold_425x623 = -1   ← 外屏
```

冷启动录屏复验:左栏卡片右缘稳定 1135px(= 折痕 430dp);缓存失效时的 38% 兜底
会是 854px,没有出现。

**3. 窄屏的轨道改成贴底横排 —— 已在 M3.14 撤回,见下。**
size class 的规矩是 **compact 宽度用贴底的栏,regular 宽度才用侧栏**。
之前一刀切竖排,在 425dp 的外屏上立刻出事:

- 表单是**右对齐取值**,竖轨道正好压在「密码」那一类值上;
- 整块表单左偏 —— 左边距 16dp、右边距 84dp;
- 一行脚注被挤得末尾「入。」孤字换行。

`EdgeRail` / `RailGroup` 加 `horizontal` 参数。主机页、编辑页窄屏贴底横排。
**终端页不跟**:它底下已经有一条按键条,再叠一条横栏在 623dp 高的外屏上太奢侈,
而且终端内容是左对齐的等宽字符网格,右侧让出 68dp 不压任何取值。

中间试错两次,都记下来:
- 先让表单"内容通到边缘、从轨道底下穿过去"(照搬主机列表那套)—— **不成立**,
  列表卡片右侧本来就空,表单的取值就在右边;
- 再给滚动容器加 `padding(bottom = RailWidth)` —— **也不成立**,那只缩短可视区、
  影响滚动上限,内容不满一屏时根本不滚,最后一行的绝对位置压根不动。

最后的做法:窄屏时轨道**实实在在占一条布局位置**(`Column { body(weight 1f); rail }`),
不浮在内容上。

**4. 其余复核发现**
- 单栏时会自动选中第一台主机 → 外屏上第一张卡片一进来就带高亮边框,像点过一样。
  自动选中只在双栏成立(右栏必须有东西可看),单栏直接传 `selectedId = null`。
- 编辑页的 `twoPane` 是在减掉轨道 68dp **之后**量的,和主机页不同源。
  改成两边都量整个窗口。
- 主机密钥指纹固定切成 **11 字符一组、两组一行**。原来让它自由折行,断点随字号浮动
  还会从字符中间切开 —— 而人要做的正是逐字符比对。放大字体下尤其明显。
- 内屏横屏右栏只有 ~330dp,两条脚注文案都正好溢出一点点造成孤字换行,缩短了。
- 单栏表单限宽 640 → 520dp:内屏竖屏 576dp 宽时,"标签在左、取值在右"要横跨半块屏。
- 死代码清掉:`SectionLabel`(Form.kt 有自己的)、`EmptyHosts` 里不可达的那一支。

**尚未验证**:真外屏只用 `wm size 1168x1712` 覆盖做了几何等价验证,没在物理外屏上跑过
(两次尝试都卡在外屏锁屏要 PIN)。合上机器实机再看一遍外屏的挖孔与圆角避让。

### M3.14 轨道回到右侧、按钮不再移动、密码加密保存(第六次会话)

**撤回 M3.13 第 3 条。** 窄屏贴底横排被用户明确否掉:按钮就该在右侧,换一块屏不该
换一个位置。现在三种形态都是右边缘竖排。这条是用户的设计决定,优先于 size class 条文。

**按钮不许动 —— 找到两处位移:**
- 主机页轨道离底叠了两层 12dp,新建页只有一层:点 ＋ 进新建页,按钮往下跳 12dp。
  现在轨道位置全由 `EdgeRail` 自己定,调用方只传 `Modifier.align(Alignment.BottomEnd)`。
- 弹键盘时轨道被顶到键盘上方。**`safeDrawing` 本身就含 IME inset**,光删 `imePadding()`
  不够,要用 `systemBars ∪ displayCutout`。键盘开着时轨道被盖住,收起后原地还在。
- 离右边距 12 → 16dp(`RailWidth` 68 → 72),胶囊右缘和卡片右缘同线。

实测(内屏横屏)主机页 / 新建页 / 新建页 + 键盘,两颗钮的 bounds **逐像素相同**;
内屏竖屏主机页 / 新建页同样相同。

**密码加密落盘。** 新增 `Secrets.kt`:Android 密钥库生成不可导出的 AES-256-GCM 密钥,
存 `iv:密文`。原来密码只在内存里,存过、连过,下次打开又得重输。实测:文件里搜不到明文;
force-stop 后重开能解回来。卸载后密钥销毁,旧密文读出空串,不崩。

**横屏双栏关于折痕镜像:** 左栏卡片止于折痕前 32dp,右栏整栏只有一条左缘(折痕后 32dp)。
原来右栏文字在 32dp、按钮在 16dp,连接/编辑/删除左右各比「认证」那列文字宽出 16dp。
连接按钮和编辑/删除同高(48dp)。详情栏的指纹也用 `fingerprintRows()` 分组 ——
原来在 `/` 处断行,第一行只剩 `SHA256:vnOd/`。

**单栏(外屏 + 内屏竖屏)单列大卡片**(约 84dp,字号放大)。原来竖屏按 264dp 自适应
排成两列,卡片 280×57dp 缩在左上角。

**顺带查出:** 单栏表单限宽后居中,竖屏内容区 536dp 比上限多出的 16dp 被左右各分 8dp,
面板文字落在 40dp、标题在 32dp。改成限宽靠左,实测所有文字左缘 32.0dp。

### M3.15 终端渲染按单元格、连接每步有上限、外屏按键重做(第六次会话)

**渲染(Codex 等显示不全)。** Rust 原来导出每行字符串时跳过宽字符占位格:「你好a」占 5 列,
导出只有 3 个字符;Kotlin 整行当一个字符串画,中文字形又不正好两格宽 —— 中文后面一路往右漂,
按列排版的程序整个错位、尾巴被裁。新增 `Term::rows()`:每行是若干「列连续、样式相同」的段,
单元格用 U+001F 分隔、宽字符占位格是空串,分隔后第 i 项就是第 col+i 列;带前景/背景色
(256 色、真彩)和粗体/暗淡/斜体/下划线/反白/删除线。Kotlin `drawRun` 逐格落到 `col×格宽`:
ASCII 连成串画,其它字符单独居中进自己的格子,太宽就横向缩放。格宽改用 100 个 M 的总宽/100
(单个 M 的像素宽度取过整,80 列累积十几像素)。实测表格里中文行和英文行的竖线同列。

**连接卡死(用户报"退出几次再连就卡在正在连接")。** 三种退出方式(✕、返回键、远端 exit)
各测 4~5 轮都**没复现**。按代码补齐所有无上限的等待:开 shell、写数据、改窗口、断开都加了
超时;保活 30s×3 → 15s×2。每条连接一个 tokio 运行时(2 线程),原来从不 destroy,
实测 4 次连断后残留 8 个 xssh-net 线程;现在关闭即释放,实测归零。连接分阶段打 logcat
(`adb logcat -s xssh`),「正在连接」显示已等待秒数。**还需要用户复现一次看日志。**

**我这轮自己引入并修掉的 bug:** 超时写成了 `block_on(tokio::time::timeout(..))` ——
计时器在进入运行时之前构造,tokio 直接 panic,**每一次**写、改尺寸、断开都失败。
单测全绿,是真机日志 `write failed: there is no reactor running` 暴露的。补了
`xssh-core/tests/live_ssh.rs`(`#[ignore]`,对真 sshd 走连接→写→改尺寸→回显→断开)。

**进终端不再自动弹键盘。** 原注释写"不主动弹",实测连接后 100ms 就弹:自动 requestFocus
就会弹(`showKeyboardOnFocus=false` 对旧版输入框无效)。键盘盖住轨道时,✕ 正好和输入法
回车键同位 —— 想断开会按成回车。

**外屏按键两行固定:** `Esc Tab ↑ Ctrl ^C` / `⋯ ← ↓ → ⏎`,⋯ 翻第二页。宽屏折行全露并加 ⏎。
终端轨道 ⌨ ✕ 拆成两个单钮胶囊,和主机页 ⌕＋ 槽位一致。

### M3.16 左滑露出「编辑」「删除」,取代长按菜单(第六次会话)

用户觉得长按菜单体验差,问左滑是否适合安卓。结论:适合 —— 国内安卓的微信、QQ、短信会话列表
都是左滑出操作,Material 3 也有列表项滑动操作。长按的问题是看不见,弹出的系统菜单又和卡片没有视觉关系。

`HomeScreen.SwipeActions`:两格 72dp(编辑 / 删除),间距 8dp,圆角与卡片同为 12dp;过半松手即打开,
按速度判断甩动;拉过头 30% 阻尼;越过打开线轻震。同一时刻只开一张,滚动或点卡片本身合上。
删除点两下(第二下是铺满两格的实心「确认删除」),详情栏和编辑页的删除也统一两步。长按改成直接打开。
单栏时打开的卡片若停在轨道那一段,先自动滚出来,免得「删除」压在 ＋ 底下。补了读屏自定义操作。

**第一版做错了:** 卡片整块向左平移 —— iOS 通栏列表那样。我们是带边框的圆角卡片,外屏实测名字整个被
推出屏幕、边框被切掉一截。改成卡片**从右往回收窄**(`Modifier.layout` 按偏移量减宽),名字左缘保持
32.0dp 不动。拖动位置在手势里自己累计,不每帧读 `Animatable.value`(snapTo 异步生效,快拖会跟不上手)。
删除后其余卡片用 `animateItem()` 滑上来补位。

实测(外屏):左滑打开、点卡片只合上不连接、长按打开、右滑合上、两步删除均正常。
**别从屏幕最右边缘起手** —— 那一条是 MIUI 的返回手势,卡片离边 16dp 正好让开。

### M3.17 Codex 整屏空白:同步刷新超时要宿主自己触发(第六次会话)

用户:进 Codex 后整屏空白,只剩顶上的主机名和 IP。和 M3.15 的"列错位"不是一回事。

**根因(读 vte 0.15 / alacritty_terminal 0.26 源码确认):** 程序用同步刷新(`CSI ? 2026 h` … `l`)
包住一帧时,vte 先把输出攒着,等结束序列或 150ms 超时 —— **超时要宿主调 `stop_sync`**,
alacritty 自己的事件循环(event_loop.rs:246)就是这么做的。我们从来没调。实测(单测钉住):
结束序列没及时到的话,**之后的所有输出**都被继续扣着,屏幕上什么都没有。
修:`Terminal::tick()`,安卓每帧在 pump 里调。

**顺带补上:** 颜色查询(OSC 10/11/12/4,`Event::ColorRequest`)和窗口尺寸查询(CSI 14t/18t,
`Event::TextAreaSizeRequest`)原来直接丢掉,问的一方只能等自己超时 —— Codex 启动时会问背景色。
现在按主题色/实测格子像素回答。OSC 52 读剪贴板故意不回答(远端不该读手机剪贴板)。

**没在 Codex 上实测** —— 它在用户服务器上,我不在用户的 shell 里敲命令;需要用户验证。

**按键按实体键盘逻辑重排(用户要求:回车必须最右,别自己乱排):**
外屏 `Esc Tab ^C ↑ ⏎ / Ctrl ⋯ ← ↓ →`,⋯ 翻页时 Ctrl、⋯、⏎ 位置不动;
内屏两行九颗 `Esc Tab ^C ^D ^Z ^L ⌫ ↑ ⏎ / Ctrl Alt | / - ~ ← ↓ →`。字号改用双指捏合。
按键面板圆角 32 → 16dp(按键 12dp),用户要求跟按键差不多。

### M3.18 会话在第 100 条消息时冻住(真正的根因,第六次会话)

M3.17 修掉同步刷新之后,Codex 能出内容但仍不完整、输入框不见。这次没再猜:

**调试录制 + 回放。** 安卓端 `Recorder.kt`(只在调试包、且 `files/record` 存在时才录;
只录服务器输出和尺寸变化,不录按键),电脑上 `cargo run -p xssh-core --example replay -- rec.bin`
用同一个终端核心回放。结果:模型里的最终画面和手机一模一样 → 不是绘制问题;输出**正好停在第 99 条消息**。

**根因:** russh 0.63 收到通道数据时先 `chan.send(ChannelMsg::Data).await` 塞进通道自己的队列
(`channel_buffer_size` 默认 100),然后才调 Handler 回调。我们只用回调、从不读那个队列,
第 100 条之后 send 永远阻塞,整个会话循环卡住:收不到、发不出、保活和断开都不处理。
任何会话用上一阵子都会冻住 —— 用户之前报的"连过几次就卡住"很可能也是它;我那时的复现每轮
只收几条消息,永远到不了 100。

**修:** `channel.split()`,读的一半交给后台任务一直读空。`tests/live_ssh.rs` 加了连敲 400 个字符
的一步:修前写到一百多个超时,修后 400 条全部收到。用户复测:Codex 基本可用;录制显示
2066 条消息、同步刷新 275/275 配对。录制文件已删、标记已移除。

**教训:** 复现要**跨过阈值**。只测"连上、看一眼、断开"永远碰不到按条数累积的 bug。

### M3.31 18 Fold 真机复核文件页(第七次会话续)

`HostEditorScreen.kt`)原来一直在工作区里没提交。真机走一遍加锁 → 连接 → 关锁,挖出三个:

1. **没加锁的主机全部连不上**(`SecretUnlock.unlockCredentials`)。它只读 `host.lockedPassword`,
   而没加锁时那是 null —— 拿空密文"解锁"得到空串,再 `host.copy(password = "")`
   把 `HostStore.load` 早就解好的明文抹掉。一律停在「这台主机还没有保存密码」。
   改成 `locked == null` 时原样保留明文。
2. **`HostStore.load` 漏读 `lockSecrets`**。每次加载都是 false:编辑页的开关显示成"关"
   (磁盘上明明锁着),更要命的是保存时 `writeSecret` 按"没加锁"用普通密钥重新加密,
   **用户没碰过开关,锁就被悄悄去掉了**。补上读取,并用密文的 `L:` 前缀兜底(老记录没这个字段)。
3. **这道锁关不掉,加锁主机改密码也存不进去**(`buildHostForSave`)。那把要求认证的密钥窗口
   原来只有 3 秒,进编辑页解的那次早过期:关锁要读旧密文 → `disableLock` 必然返回 null,
   永远是「没能关掉这道锁」;一直锁着的主机改密码 → `writeLocked` 抛异常被 `getOrElse` **静默**
   吞掉退回旧密文,界面说存好了、密码其实没变。改成**保存前凡是要动那把密钥就现验一次**,
   窗口 3 秒 → 10 秒。

**真机复核(18 Fold,`.review` 副本)**:开锁(密文变 `L:` 前缀、`lockSecrets: true`)→ 详情页显示
「密码」而不是「未保存」→ 连接弹解锁、验完真的发起连接(报的是黑洞地址的 `ssh: Disconnected`,
不是凭据错误)→ 编辑页开关正确显示「开」、密码解出来 → 关锁(密文变回普通、`lockSecrets: false`)
→ 重启后直接连接不再弹框、密码没丢。整圈通过。

**生物识别本身要用户的手**:自动化只能把流程推到弹框那一步,每次都得请用户验一下
(框是系统安全窗口,截图全黑,只能靠 `dumpsys window | grep mCurrentFocus` 看到 `com.android.systemui`
拿到焦点来判断它弹出来了)。

### M3.51 密码框丢字;指纹改成只在连接时验(第八次会话续)

用户:"你现在搞的所有 SSH 都连接不上了";"人家输入密码点保存,勾选了指纹启动,你要识别一次干嘛呢?
……指纹认证只有什么情况下有意义?就是用户连接这个 SSH 的时候"。

**1. 连不上的真因:密码框会丢字(`Form.kt`)。**
输入框同时存着两份文本 —— 自己的 `field` 和外部的 `value` —— `syncedField` 的规矩是
"两份不一样就丢掉自己的、用外部那份覆盖"。外部是异步回来的,打字稍快就慢一拍,新敲的字被旧值盖掉。
**13 位的密码存下来只剩 8 位**,而且一声不响:密码框显示圆点,看不出少了字,要等连服务器被拒才知道。
改成**输入框自己的状态是唯一真相**,外部的值只有在不等于"上一次交给外部的文字"时才采纳
(那才说明外部真的改写过:端口只留数字这类)。
从密文长度反推明文长度(GCM 密文 = 明文 + 16 字节)是个好用的非侵入检查,不用看到密码本身。

**2. 一条把我带偏一个多小时的日志**:`Log.w(..., "${e.javaClass.simpleName} ${e.message}")`,
uniffi 的异常类叫 `Message`,于是普通的「认证失败」打出来是 **`Message authentication failed`** ——
读着像 MAC 校验失败。我照这条线索去查密钥交换和加密套件,做了一堆无效对照
(还一度改了 russh 的 cipher 顺序,又撤了)。**类名和消息之间必须有分隔符**,现在是 `[Message] ...`。

**3. 指纹改成只在连接时验(`Secrets.kt`)。**
原来上锁和解锁是同一把对称密钥,所以保存密码也要验一次 —— 没有意义:密码是用户在自己已解锁的
设备上、自己的 App 里亲手打的。改成**一对 RSA 密钥**:密钥库的规矩是只有私钥操作要认证,
所以公钥加密(保存)一声不响,私钥解密(连接)才弹框。正文仍用一次性 AES 密钥加密,
公钥只包那把 AES 密钥(RSA 直接加密装不下几 KB 的私钥)。
密文格式 `L:包着的AES密钥:iv:密文`(3 段);老的对称密文 `L:iv:密文`(2 段)照旧能读,老密钥保留不删。

**RSA-OAEP 在 Android 密钥库上踩了三个坑,缺一个都是 `IllegalBlockSizeException`(message 为 null,
什么都看不出来)**:
  1. **OAEP 参数两边都要写死**:公钥加密在普通 JCA 里 MGF1 跟主摘要走 SHA-256,
     密钥库解密那边 MGF1 默认 SHA-1。统一成 `OAEPParameterSpec("SHA-256","MGF1",SHA1,…)`。
  2. **两个摘要都要授权**:`setDigests(SHA256, SHA1)`。只授权 SHA-256 的话,带 MGF1-SHA1 的
     参数会被密钥库拒掉。
  3. **公钥要"摘出来"再用**:直接拿 `store.getCertificate(alias).publicKey` 去加密,Cipher 会落到
     AndroidKeyStore provider 上、按它自己那套参数走。要用 `KeyFactory` 按 X509 编码重建一个
     普通公钥对象,加密才走标准 provider。

顺带:`HostStore.writeSecret` 里"封不上就退回旧密文"的**静默兜底加了日志** —— 它意味着
"用户改了密码、界面说存好了、其实没改",不打日志完全看不见,这一轮骗过两次排查。
编辑页也不再解锁回填密码(解密要验指纹,而改主机不该验),密码格空着、占位字显示「已保存」,
空着保存不动那条密文。

**真机复核(小米平板 9 Pro Max),整圈都跑过**:
  1. 新建并加锁 → 保存**不弹框**,密文是 3 段式。
  2. 连接 → **弹框**,验完密码正常解出、真的发起连接。
  3. 关掉这道锁 → **弹一次框**(要把旧密文读出来换成普通密钥存),关完
     `lockSecrets: false`、密文没有 `L:` 前缀、**明文长度和原密码一致(密码没丢)**。
  4. 关锁之后再连 → **不弹框**,照样连得上。
用户的真实主机(旧的 2 段式对称密文)不受影响,照常连上。

### M3.53 三轮复核:我自己修出来的两个错(第八次会话续)

**这一节主要是记我自己的两次翻车,别再犯。**

用户报"13 位的密码存下来只剩 8 位"。我改了 `FormField` 的对齐判据:
  1. 第一版判据是"和我上次交出去的文字不一样才采纳"。那个量在每个写入点都跟 `field.text`

    + 整屏缓冲
  - 进程被杀后重启,凭一个 `termHostId` 就自动重新拨号(加锁主机还白弹一次指纹);
    `screen` 的初始化早就判了 `SessionRegistry[it] != null`,那个 `LaunchedEffect` 漏了
  - 终端 `resize(0)` 会让 `size.rows - 1` 在 usize 上溢(界面那边碰巧夹了,属潜在崩溃)

### M3.58 全面复核:凭据丢失路径、密文状态、安卓单测从零建起(第十次会话)

**1. 加锁主机换登录方式会丢凭据(`HostEditorScreen.kt`)**

`HostDraft.build()` 里三条 `locked*` 密文原来无条件透传。规则抽成 `carriedSecrets(key, keyLocked)`,配 `CredentialCarryTest`。

**2. 加锁记录可能带上一条普通密钥的密文(最严重的一条)**

`buildHostForSave` 的兜底:这次没封出内容(`enableLock` 对空明文返回空串)时沿用 `host.locked*`,
**却没看那条是不是 `L:` 前缀**。开锁路径上,主机原本没加锁、手里攥着普通密钥的密文 ——
写回一条 `lockSecrets = true` 的记录之后,`Secrets.open` 只认普通密钥、`readLocked` 只认 `L:`,
**两边都读不出来**:界面写着「已保存」,磁盘上的密码永久解不开。

`carriedLocked(sealed, previous, locking)` 拒绝这种组合。**阴性对照做过**:把判断临时禁用,
只有为它命名的那条测试失败,其余全过。

**3. 「没存过」和「存了但读不出来」分不开(`Secrets.kt` / `HostInfo.kt`)**

重装、清了应用数据、密钥库被换掉之后,磁盘上的密文永久解不开,而 `Secrets.open` 返回空串 ——
界面说「未保存」,用户以为自己从没存过。现在 `HostStore.load` 解密时就把"原文不空、明文却空、又不是加锁的"
记进 `Host.unreadableSecrets`(`unreadableSecrets(sealed, plain)`),详情页据此标出「凭据 · 密码 读不出来」,
「登录方式」不再说「未保存」。加锁的密文不算坏(那是等着解锁)。测试:`UnreadableSecretsTest`。

> **第一版是坏的,二次复核时改掉(第十二次会话)**:原来是在详情页拿 `host.locked*` 去判(`brokenSecrets`),
> 可 `load` 只把**加锁**的密文放进 `locked*`,而加锁的又被排除在外 —— 这一行**永远不出现**。
> 测试之所以是绿的,是因为它手工造了 `Host(lockedPassword = "YWJj:ZGVm")`,一个 `load` 永远产生不了的状态。
> `SecretState` / `readPlainOrNull` / `brokenSecrets` 随之删掉;新测试只用 `load` 真会给的形态,

用户主机 `DGX Node 0`(`user@192.168.1.100:22`,密码 + 生物识别加锁),`xssh_hosts.xml` 测前测后逐字节一致
(sha256 `3A2679C0…`),备份在 `D:\Android\pad\verify-2026-09-26\`。
**最有价值的是「14 个字段逐项一致」那条**:它直接压住了 M3.58 第 2 条修的那个洞。判据是**逐字段比对**
而不是"看着还在" —— 密文被抹成空、或被换成普通密钥的密文,哈希都会变。
实体键盘那几条(DECCKM、Ctrl+C)还没在真机上试过。

**「切私钥」那一趟的真实行为(重要)**

切到私钥状态**保存后**,磁盘上 `password` 变成空、`keyData` 是新私钥 —— 这是 `carriedSecrets(key = true)`
的既定规矩("换成私钥就不留密码,反之亦然"),**不是 bug**。但要注意它的后果:

> 用户如果切到私钥登录并存了盘,再切回密码时,**密码格是空的**(草稿的 `initial` 已经是那份没有密码的记录)。
> 他必须重新输一次密码。这是既有设计,不是这一轮引入的,但值得知道 ——
> 想保住密码就不能在中途存盘。

**没验成的:主机密钥指纹的还原**

想把我手上备份的指纹写回设备时发现:**任何经 `run-as cp` 推进 `shared_prefs/` 的文件,应用都读不到**
(字节、权限、属主、SELinux 上下文看着全对,`ls -lZ` 与应用自己写的一模一样)。表现是主机列表变空,
`HostStore.load()` 的 `runCatching{}.getOrDefault(emptyList())` 把读取失败静默吞成了空列表。

对比实验说明问题在写入方式而不在内容:
- 应用**自己写**的文件(`rebuilt2.xml`,2118 字节)→ 能读 ✅
- 同一份内容经 `cp` 推回去 → 读不到 ❌

**结论:`shared_prefs/` 不要用 `cp` 写。** 要改设置数据就走应用自己的界面,或者接受"推完就得由应用重建"。
之前会话里往 `files/` 推私钥能成功,那是另一个目录,别把经验套过来。

## 5. 关键坑(踩过,别再踩)

102. **横屏时 `input` 的坐标 ≠ uiautomator 的坐标**。平板锁定横屏(`user_rotation=1`)时
     `dumpsys window displays` 报 `init=2272x3408` 而 `cur=3408x2272`、`mDisplayRotation=ROTATION_90`:
     这是**同一块屏转了个方向**,不是分辨率变了。`input tap` 要的是**未旋转的物理坐标**,
     而 `uiautomator dump` 给的是**旋转后的显示坐标**。换算关系不稳定,别硬算。
     **可靠做法:先 `adb shell settings put system user_rotation 0` 转成竖屏**,两边就同空间了,
     点完 `put system user_rotation 1` 还原(用户原设置:锁横屏 + 关自动旋转)。
     另一个更省事的路子:**键盘注入是可靠的**(`input keyevent TAB` 让焦点移动、
     `keycombination KEYCODE_CTRL_LEFT KEYCODE_S` 保存、`KEYCODE_CTRL_LEFT KEYCODE_E` 打开编辑),
     点击打不进去时先试键盘。
103. **`screencap` 全黑未必是 SECURE 也未必是休眠**。遇到过:屏幕 `mScreenState=ON`、亮度 72、
     没有 SECURE、`isKeyguardShowing=false`,但截图纯黑 —— 原因是**主题刚切成深色,那一帧正好是重建过渡**。
     判据:看 PNG 的**文件大小**(纯黑 36KB vs 正常 185KB),等两秒重截一次。
     另外**聚焦密码框时全黑是正常的**(坑 100c 那条 `FLAG_SECURE` 生效),别当成故障。
104. **`shared_prefs/` 的文件不能用 `run-as cp` 写回去**(见 M3.59)。要改就动界面。
105. **用脚本改这份文档时,锚点必须先查出现次数,并注意它是 CRLF**。
     `String.replace(锚点, …)` 只换第一处;而**字符串形式的第二参数里 `$&`、`` $` ``、`$'` 是特殊模式**
     (`` $` `` = 匹配之前的全部文本)—— 文档里写了 `~$` 后跟反引号这种内容时,
     它会**把整份文档复制一遍**。这一轮就把它写成了 1941 → 3765 行的两份,而且**第一次还报告"写入成功"**。
     **用函数式替换**(`s.replace(anchor, () => text)`),并且改完查 `## 0` 这类唯一标记的出现次数。


1. **DSR 应答**:终端事件不回写 → 远端程序挂起(ConPTY 必现;vim 同理)。已修 + 单测。
2. **cargo-ndk 4.x**: API level 是 `-P`;`-p` 已被 cargo 占用(会报 `unknown package: 26`)。
3. **AGP 9 内置 Kotlin**:必须删掉 `org.jetbrains.kotlin.android` 插件;Compose 插件保留。
4. **uniffi 异常字段名 `message`** 与 Kotlin `Exception.message` 冲突 → 用 `#[uniffi(flat_error)]`。
5. **改 Rust 后必须重建 `.so`**(`cargo ndk ...`)再打 APK,否则 APK 里还是旧库(今天因此浪费过一轮排查)。
6. **adb 进程会占住输出管道**导致工具误杀:所有 adb 调用重定向到文件,或结束加 `adb kill-server`。
7. **锁屏/息屏时 screencap 全黑**;多显示器必须 `-d`。
8. Windows OpenSSH 靶机需 `ListenAddress 0.0.0.0` + 入站防火墙规则才对外可达。
9. ConPTY 写端被 drop 会连带终止子进程(devpty 已用 `keep_input_open` 规避)。
10. **MIUI 联网控制页**:搜索模式会隐藏页签;清空搜索后列表可能短暂为空(等一下或退出搜索再进);
    X-SSH 名字红色 = 受限;`uiautomator dump` 看不到搜索结果的业务行,只能用截图判读。
11. **App 联网被禁的表征**:`am start` 正常、UI 正常,但连接一律超时(core 的 15s `Timeout`);
    用 `run-as <pkg> ... nc` 可快速区分"网络被禁"与"服务端问题"。
12. **Android 16+ 本地网络保护**:连 `192.168.x.x` 还要 `ACCESS_LOCAL_NETWORK` 运行时权限,
    只有 `INTERNET` 不够;被拒时同样是**静默超时**,和 MIUI 封锁、服务端不可达长得一模一样。
    排查口诀:App UID 连**公网**也超时 → 整体封锁(MIUI);只有内网超时 → 本地网络权限。
    `adb shell appops get <pkg> ACCESS_LOCAL_NETWORK` 能看到 `ignore` 与 `rejectTime`。
13. **`adb shell input text` 的空格**:要写成 `%s`(`input text 'echo%shi'`);直接写空格会丢词。
    另外它是连续快速提交,正好能压出输入法相关的竞态(见坑 14)。
14. **隐藏输入框的哨兵竞态**(已修):终端用一个零宽字符作哨兵,提交后重置输入框。重置是
    **异步生效**的,输入法同帧连发时,后一个事件里还是旧内容,按固定哨兵裁前缀会把上一个
    字符重复发出("echo"→"echoo")。改成两个零宽字符轮换,用哨兵区分「重置生效」与「陈旧事件」。
15. **终端要主动抢焦点**(已修):连上后若不点一下屏幕,隐藏输入框没有焦点
    (`dumpsys input_method` 里 `mServedView=null`),外接键盘和 `input text` 都进不去。
16. **`input tap` 在 MIUI 上会丢事件**(实测同一坐标连点 5 次只生效 1 次)。表现是
    「按钮点了没反应」,极易误判成代码 bug —— 本次就为此查了一轮。自动化里一律写成
    **点到界面变化为止**的重试循环,并用 `uiautomator dump` 判读结果,别只点一次就下结论。
    判断注入本身是否还活着: 点另一个按钮(如「返回」)看界面是否变。
17. **`am start` 要带 `-S`**:App 已在前台时同一 component 的 intent 走 `onNewIntent`,
    而 `MainActivity` 只在 `onCreate` 读 `devAutoConnect`,于是调试参数被静默忽略
    (只在输出里留一句 `Warning: Activity not started`)。
18. **`uniffi(flat_error)` 只带 Display 文本过边界**,字段不过去。所以两个主机密钥错误的
    Display **就是指纹本身**,宿主直接拿来存/比;人话措辞在 Kotlin 侧拼。改这类语义时
    记得同步 `FfiError` 的注释,否则下一个人会去解析字符串。
19. **折叠形态可以用命令模拟,不必真去掰机器**:`cmd device_state print-states` 列出
    CLOSED/HALF_OPENED/OPENED…,`cmd device_state state 2` 进半折(桌面模式),
    `state reset` 还原;窄屏形态用 `wm size 1168x1712` 覆盖成外屏尺寸(`wm size reset` 还原)。
    **但切到 CLOSED 后外屏是锁屏**,需要 PIN 才能进应用,远程测不了外屏真机。
20. **铰链坐标是「窗口」坐标**:拿它做分栏时,外层容器**不能**先加 `safeDrawingPadding`,
    否则挖孔在侧边(内屏横屏 51dp)会把分界线整体推离折痕。内边距要放进各栏自己加。
21. **`staticCompositionLocalOf` 不比较新旧值**:提供一个每次重组都新建的 data class,
    会让整棵树全量重组。`rememberAdaptive()` 里必须 `remember` 住。
22. **手写 `pointerInput` 手势会丢掉点击语义**,读屏软件点不动,`uiautomator` 也看不到

23. **终端内容是 Canvas 画的**,`uiautomator dump` 拿不到里面的字,自动化断言只能靠截图;

24. **`widthIn(max=…)` 必须写在 `fillMaxWidth()` 之前**。反过来写,`fillMaxWidth` 先把
    最小宽度钉成整屏宽,`widthIn` 的上限被最小值顶掉,等于没写(编辑页顶栏因此没收窄)。
25. **对齐要量,不能看**。`uiautomator dump` 的 bounds 是精确像素(密度 2.75),

27. **真机会自己休眠回锁屏**,之后需要 PIN/指纹才能继续调试(外屏尤其容易)。

29. **Compose 里关资源不能用 `rememberCoroutineScope()`**:界面离开组合时它自己先被

46. **一个现象可能压着两个成因**。修完第一个还在复现,不代表第一个没修对 ——

48. **异步到达的窗口信息(折痕/尺寸)要缓存**,否则每次冷启动都会先按兜底值排一帧版。
49. **`BoxWithConstraints` 的 `maxWidth` 进了 Column/Row 的 lambda 就取不到了**
    (作用域被遮住),要先存成局部变量。
50. **Git Bash 会把 `/data/...` 改写成 Windows 路径**,`adb shell am start -n pkg/.Act` 也会被吃掉。
    所有 adb 命令前加 `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`。
51. **MIUI 的挖孔 inset 不可信**:Fold 内屏平时报 0,键盘动画前后报 140px。页面 inset 用 systemBars ∪ ime,
    挖孔只按 `Display.getCutout()`(API 29+,随旋转)单独避让。180° 翻转不触发配置变更,要监听 DisplayListener。
52. **Activity 重建时旧实例的 onStop 晚于新实例的 onStart**。任何"前台与否"的布尔都会被写错,用计数。
53. **Compose 的 OverscrollEffect 在内容不满一屏时不会被调用**(scrollable 不分发越界);回弹要自己接 nestedScroll。
54. **`BackEventCompat.progress` 在 MIUI 上带缓动**(拉到 1/3 屏就 0.95);跟手的返回用 `touchX` 自己算。
    拖动期间用匀速 tween,弹簧按时间取进度同样不跟手。
55. **键盘动画期间别让重活跟着每帧跑**:画布变尺寸 = 整屏重画,行列变更 = PTY resize + 远端重画。都要等停稳再做。
56. **Python 脚本改 Kotlin 时别在普通字符串里写 `\x1b`**,会被写成真正的 ESC 字节;改完 `grep -c $'\x1b'` 查一遍。

    焦点就得在一个**不是输入框**的节点上;要在输入框里抢按键,用 `onInterceptKeyBeforeSoftKeyboard`(只抢 Ctrl/Alt,别抢组词要用的键)。
58. **小米输入法会吃掉 Esc**(输入框聚焦时第一下 Esc 只让输入框失焦),`onPreviewKeyEvent` 收不到。
59. **每个按键 `launch(Dispatchers.IO)` 会乱序**。写远端必须串行(一个队列一个协程)。
60. **没有任何焦点时 Compose 收不到按键**。要页面级快捷键,页面根节点自己 `focusable()` 并在插着键盘时请求焦点。
61. **PowerShell 里 `adb exec-out screencap -p > x.png` 会把 PNG 写坏**(按文本重编码)。先 `screencap` 到 `/sdcard` 再 `adb pull`。
62. **`sdkmanager.bat` 的包名里有分号**,经 cmd 转一道会被拆开(`Package platforms not found`)。用 `--package_file=`。
63. **`adb shell input keyboard …` 模拟的是实体键盘**(`keycombination KEYCODE_CTRL_LEFT KEYCODE_C` 可用),
    `input mouse scroll x y --axis VSCROLL,5` 模拟滚轮;它们不改 `Configuration.keyboard`,所以只在真插着键盘时走直通分支。
64. **`adb shell` 的参数经过设备端 sh**:`input text` 里的 `(`、`%`、`\` 会被解析,测试命令挑不含这些字符的。
65. **小米输入法接实体键盘组拼音时不报 composition**,别指望 `TextFieldValue.composition` 判断"在不在组词",用 `ImeBuffer` 的推断。
70. **小米的文件选择器(「安全访问」)按媒体库列文件**:`adb push` 进去的文件要等媒体扫描
    (`content call --method scan_volume --uri content://media --arg external_primary`),而且「我的平板 → Download」
    目录视图还是不显示,要从「浏览 → 下载」分类里找。第一次打开「文件管理」要用户同意它的协议(不能替用户点)。
71. **鼠标每按一下,Compose 都会清掉当前焦点**(键盘操作模式下点击 = 重新分配焦点)。没法聚焦的地方被点了,
    焦点就没了。用鼠标的界面都要考虑"点完之后焦点回哪儿"。
72. **小米输入法接实体键盘时无视 `KeyboardType`**:Uri / Ascii 都照样组拼音。只会是英文的输入框要自己在输入法之前收字符。
67. **长按不能只靠"一段时间没有事件"判断**:手指按着时系统一直在报位置(抖动 / 零位移,`input swipe` 同样),
    超时永远等不到。每个事件都要看按住多久了。
68. **adb 注入的鼠标事件不带按键状态**(`buttons` 全空),触控板轻点也可能这样;判断"左键"要写成"不是右键 / 中键"。
69. **`input mouse swipe/tap` 能测鼠标拖选、双击;`input motionevent DOWN/MOVE/UP` 能测"按住再拖"**(`input swipe` 一开始就在动,测不了长按)。
66. **测搜索别用匹配不上的词**:搜「local」匹配不到「本地靶机 / 127.0.0.1」,回车理所当然没反应,差点当成 bug 查了一轮。
73. **同一条 SSH 连接上开第二个通道(SFTP),Handler 的回调不分通道**:要记下 shell 的 ChannelId,只转它的事件,不然别的通道一关终端就判定断开。
74. **uniffi 导出的对象方法别叫 `close`**:Kotlin 绑定里对象本身实现 `AutoCloseable`,生成出来就是重名的两个 `close()`。
75. **`AnimatedContent` 切换的那一小段,退场的内容还在组合里、还读得到最新状态**:用计数器请求焦点时,退场那一栏也会响应并把焦点抢走
    (切回终端后敲键盘没反应)。只把请求传给进场的那一栏。
76. **系统「存储到…」选择器一确认就建好了文件**:之后决定不传(正忙、出错、取消)要自己 `DocumentsContract.deleteDocument`,不然留 0 字节 / 半截文件。
77. **Pad 截图缩到 1363 宽后,换回屏幕坐标是 ×2.5**(物理 3408×2272 横屏),别按 2.35 算 —— 点歪了会以为按钮没反应。本机靶机走 USB 反向代理,400MB 一秒多就传完,测取消要用几 GB 的文件。
78. **MediaStore 写下载目录**:`RELATIVE_PATH` 以 `Download/` 开头、按扩展名给 MIME(给错了系统会给文件名补扩展名);
    写完要把 `IS_PENDING` 改回 0,不然别的应用看不见;重名时系统改名,实际名字要回头查 `DISPLAY_NAME`。
79. **系统「允许访问文件夹」、别的应用首次启动的协议都不能替用户点**:测上传文件夹 / 下载到… / 打开时要请用户在场。
80. **别的电脑装的 debug 包,这台电脑覆盖不了**(签名不同)。卸载会删掉 Keystore 里的密钥 → 已加密保存的密码全部作废。
    真机复核用 `'-PxsshIdSuffix=.review'` 装成另一个包并存,测完卸掉副本。
81. **按钮换页落点不变,也意味着危险按钮的落点会被"连点"命中**:新页面最下面那颗如果是 ‹,连点着退出来就会点到终端页的 ✕。
    危险操作(断开 / 删除)所在的位置,相邻页面同一个位置不要放"会被连点"的按钮。
82. **按通道过滤事件时,登记要早于任何可能到来的数据**:通道一开就登记,别等"请求成功"之后 —— 服务器的第一段输出紧跟着应答就来。
83. **中英混排的等宽字体要成对选**:英文正好 0.5em、中文 1em 才能"中文 = 两格"不留缝;中文按英文字体的基线摆,
    别按各自字体的行顶摆(CJK 字体的 ascent 大,会整体下沉)。系统 `monospace` + 界面字体回退 = 两套设计,一看就散。
84. **终端里别占 Ctrl+Space**:它是 NUL(Emacs 设标记)。切输入法用 Shift(单按)/ Ctrl+Shift+Space。
85. **`TextMeasurer` 的缓存不看颜色**:同一串字换色再 `measure` / `drawText(measurer, …)` 拿到的是旧颜色。
    会变色的字(终端、主题切换)一律 `drawText(layout, color = …)` 在画的时候给颜色和装饰。
86. **本机靶机 sshd 要 `-o PerSourcePenalties=no`**:OpenSSH 10 会把"连上不认证就断"的来源罚几秒,手机经 adb reverse 都算 127.0.0.1,
    连几次失败后就一直 `ssh: Disconnected`;`adb reverse` 也会失效(nc 连得上但没有横幅),`--remove-all` 后重建。
88. **中英要"工整",字体得按 0.5em 挑**:英文半格、中文一格才是两格对齐。0.6em 的等宽字(JetBrains Mono 这些)
    中文塞两格必留缝;混排的行高、基线也要由**一套**字体定死,别让每款字体各摆各的。
90. **边距不能一页一个写法**:先定"盒子线 / 标题线 / 盒内文字"三条线(见 Components 顶上的版心),
    每页都从这三条线取值;页面里临时加 `+ BoxPad`、`end = 88dp` 这种,几页之后就各长各的样。
91. **回弹动画一定要能被下一次触摸打断**:不打断的话弹簧和手指抢同一个位移量,整段滑动会被"收橡皮筋"吃掉,
    表现是"滑不动 / 滑不到头",但帧率完全正常 —— 先分清是掉帧还是位移被吃,再动手。
92. **轨道上的玻璃会折射身后的内容**:胶囊中间时不时出现的淡淡光斑是下面卡片的图标块透上来的,
    跟着列表滚动 —— 那是 Liquid Glass 的效果,不是画错了。
93. **画线字符别跟着换字体**:制表符 / 方块要和格子严丝合缝,固定用建格子那套字(Iosevka),否则表格竖线断成一节一节。
94. **18 Fold 插电是「充电器供电」不是 USB**:`svc power stayon usb` 不生效,要 `svc power stayon true`,测完 `false`。
    Win+Space、键盘的「中/英」键在小米上被系统截走切输入法,应用收不到,别指望它们。
95. **MIUI 的「USB 安装」开关会自己过期**:装过一次不代表下次还能装 —— 隔一阵或重新插拔之后
    同样报 `INSTALL_FAILED_USER_RESTRICTED`,而且手机上**不弹任何框**,只能请用户再去开一次。
    所以**测试副本装上就别卸**,卸了再装又要麻烦用户一轮。
96. **日志里类名和消息之间一定要有分隔符**。`"${e.javaClass.simpleName} ${e.message}"`
    碰上 uniffi 生成的异常类 `Message`,普通的「认证失败」打出来就是
    **`Message authentication failed`** —— 读着像 MAC 校验失败。照这条线索能一路查到
    密钥交换和加密套件上,白花一个多小时、还改错一次 russh 配置。现在是 `[Message] …`。
97. **"界面说成功了、其实没成功"是最贵的 bug**。这一轮踩到三处:密码框丢字(圆点看不出
    少了字)、`writeLocked` 失败静默退回旧密文、`Secrets.seal` 出错返回空串。
    **凡是"出错也别崩"的兜底,都要留一条日志** —— 否则查的人完全看不见。
98. **`arcTo` 画整圆:起点必须是圆的顶点**(圆心落在起点正下方 r 处)。从别处起笔,
    圆会歪到一边去(眼睛图标的瞳孔跑出眼眶,看着像条鱼)。
99. **MIUI 会挡住 adb 装新包**:`INSTALL_FAILED_USER_RESTRICTED: Install canceled by user` 不是签名问题,
    是「开发者选项 → USB 安装」(要小米账号验证)关着 —— `settings get secure install_non_market_apps` 显示 1
    也照样挡。这是用户的安全设置,**不要自己去改**,请用户在手机上开或确认安装框。并存的 `.review` 副本同样被挡。
100. **`onDispose` 里读 State 读到的是"现在",不是"当初"**。`DisposableEffect(flag)` 在
    `flag` 翻转时重跑,onDispose 先执行,那一刻 `flag` 已经是新值 —— 想"只撤销自己做过的事"
    必须在副作用体里把值抄成局部变量。实测代价:`FLAG_SECURE` 挂上再也摘不掉。
100b. **`FLAG_SECURE` 按窗口算,平板的浮层是另一扇窗**。手机上编辑页和主界面同属
    Activity 那扇窗,平板上是 `Dialog`(`dumpsys window windows` 里带 `DIM_BEHIND` 的那条),
    只挂 Activity 挡不住浮层里画出来的东西。Compose `Dialog` 的 `SecureFlagPolicy.Inherit`
    只在浮层那层重组时求值,靠不住。取窗口:`LocalView.current.parent as? DialogWindowProvider`。
100d. **17 Ultra 插电后 `svc power stayon usb` 不管用**(同 Fold,坑 94),要 `svc power stayon true`,测完 `false`。
100c. **小米输入法给密码框挂 SECURE,会把整屏截图弄黑**。这会**掩盖**应用自己的漏洞
    (看起来"保护住了",其实是输入法在挡)。测应用的保护要用不受输入法影响的判据:
    读 `dumpsys window` 的 `fl=`,或看最近任务缩略图(那张快照里没有输入法)。
    锁屏时 `screencap` 同样全黑 —— 测之前先确认 `showing=false`。
101. **验一条"闪一下"的界面 bug,先想清楚有没有对照**。逐帧录像能证明"看不到跳动",
    不等于证明"代码走了那条分支" —— 面板淡入期间旧代码可能同样看不出来。
    没有阴性对照就老实写"现象上过、路径未证实",别把两者混为一谈。
106. **测试别手工造生产代码产生不了的状态**(第十二次会话):`SecretStateTest` 造了 `Host(lockedPassword = 普通密文)`,
     而 `HostStore.load` 只往 `locked*` 里放加锁的密文 —— 测试全绿,功能从来没生效过。写测试前先查清楚
     被测函数的输入在生产里是**谁、怎么**造出来的;最好直接测那个造的地方。
